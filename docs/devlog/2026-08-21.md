# 개발 기록 — 2026-08-21

## 프로젝트 설정

MutePilot을 시작하기 위해 GitHub 저장소를 만들고 로컬 저장소와 연결했다. `origin`이 올바른 저장소를 가리키는지, 안정 브랜치가 `main`인지 확인했다. 프로젝트 범위와 문서 작성, 검증, Git 작업 방식을 계속 지킬 수 있도록 루트에 `AGENTS.md`도 추가했다.

이 과정에서 로컬 변경은 아직 저장되지 않은 파일 상태이고, commit은 로컬 Git 기록에 남기는 작업이며, push는 그 commit을 GitHub 원격 저장소로 보내는 작업이라는 차이를 정리했다. branch를 사용하면 안정적인 `main`과 개발 중인 작업을 분리할 수 있다는 점도 확인했다.

## 오늘 목표

MutePilot의 첫 실행 가능한 Windows 프로그램을 만드는 것.

## 진행한 내용

* `feature/v0.1-core` branch에서 작업을 시작했다.
* GitHub 문서를 자연스러운 한국어로 작성하도록 `AGENTS.md`에 영구 규칙을 추가했다.
* `MutePilot.sln`과 `src/MutePilot/MutePilot.csproj`로 .NET 8 WPF 기본 구성을 만들었다.
* 어두운 배경의 간단한 메인 창에 `Master Audio`와 `Application Shortcuts` placeholder를 배치했다.
* 아직 구현하지 않은 마스터 음소거 버튼은 비활성 상태로 표시했다.
* 창 하단에 `Made by 유성우`를 표시했다.
* 제품명과 버전 `0.1.0`, 대상 프레임워크 `net8.0-windows`를 설정했다.

음소거, 오디오 세션 조회, 전역 단축키 기능은 이번 작업에서 구현하지 않았다.

## 새롭게 알게 된 내용

* **C#:** 이번 프로그램의 동작을 작성할 언어다. 이번 단계에서는 WPF 템플릿이 만든 최소 code-behind만 사용했다.
* **.NET 8:** C# 프로젝트를 만들고 복원하고 빌드하는 데 필요한 SDK와 실행 환경을 제공한다.
* **WPF:** XAML로 Windows 화면을 구성하고 C# 코드와 연결하는 데스크톱 UI 기술이다.
* **`.sln`:** 여러 프로젝트를 한 번에 관리하고 빌드할 수 있게 묶어 주는 솔루션 파일이다.
* **`.csproj`:** 대상 프레임워크, WPF 사용 여부, 제품 버전처럼 프로젝트 빌드에 필요한 설정을 담는다.
* **`dotnet build`:** 소스와 XAML을 실제 실행 파일로 만들 수 있는지 확인하는 명령이다.

## 문제와 해결

처음 확인했을 때 .NET 8 Runtime만 있고 SDK는 설치되어 있지 않아 프로젝트를 만들 수 없었다. 이 상태에서 다른 버전으로 대신 진행하지 않고 작업을 중단한 뒤, Windows x64용 .NET 8 SDK를 설치했다. 설치 후 `dotnet --list-sdks`에서 `8.0.424`가 표시되는 것을 확인하고 작업을 다시 시작했다.

그 외에 빌드나 실행을 막는 문제는 없었다.

## Windows 마스터 음소거 개발

### 진행한 내용

* `feature/v0.1-master-mute` branch에서 Windows 마스터 오디오 제어 기능을 구현했다.
* UI와 Windows 오디오 제어 코드를 분리하기 위해 `IAudioService`와 `AudioService`를 추가했다.
* 앱을 시작할 때 기본 출력 장치의 실제 음소거 상태를 읽어 화면에 표시하도록 연결했다.
* 버튼을 누르면 현재 상태의 반대로 설정하고, 결과를 다시 읽어 상태 문구와 버튼 문구를 갱신하도록 만들었다.
* 기본 장치가 없거나 Core Audio 호출이 실패하면 앱이 종료되지 않고 안내 문구를 표시하도록 처리했다.

### 새롭게 알게 된 내용

* **Windows Core Audio:** Windows의 기본 출력 장치와 endpoint mute 상태를 다룰 수 있는 API다.
* **기본 오디오 출력 장치:** 사용자가 Windows에서 현재 기본으로 선택한 재생 장치다. 장치가 바뀔 수 있으므로 서비스에서 작업할 때마다 다시 가져오도록 했다.
* **UI와 오디오 로직 분리:** WPF 화면에는 API 호출 코드를 직접 넣지 않고 `IAudioService`를 통해 상태만 요청했다. 나중에 오디오 구현을 바꾸거나 오류를 확인하기가 더 쉬워진다.
* **NAudio:** Windows 오디오 API의 COM interop을 직접 많이 작성하지 않아도 되게 도와주는 .NET 오디오 library다. 이번에는 필요한 Core Audio endpoint 기능만 쓰기 위해 `NAudio.Wasapi 2.3.0`을 선택했다.

### 문제와 해결

현재 NAudio 최신 major 버전은 .NET 9 이상을 요구해 .NET 8 프로젝트에 맞지 않았다. .NET 8과 호환되는 안정 버전 중 필요한 WASAPI 기능만 담은 `NAudio.Wasapi 2.3.0`을 지정해 추가했다.

빌드와 앱 시작을 막는 문제는 없었다.

### 확인 결과

* `dotnet restore MutePilot.sln`: 성공
* `dotnet build MutePilot.sln --no-restore`: 성공, 경고 0개, 오류 0개
* GUI 실행: 성공. 제목이 `MutePilot`인 창이 열리고 바로 종료되지 않았다.
* 시작 상태 조회: 성공. 테스트 당시 UI에 `현재 상태: 음소거 해제`가 표시되고 `음소거` 버튼이 활성화된 것을 확인했다.
* 실제 음소거 전환: 자동 검증하지 않음. 사용자 오디오를 임의로 바꾸지 않기 위해 버튼을 누르지 않았으며 수동 확인이 필요하다.
