# 개발 기록 — 2026-08-22

## 오늘 목표

fullscreen 게임에 포커스가 있을 때 단독 F키가 기존 `WM_HOTKEY` 경로로 들어오지 않는 문제를 보완하고, 단축키 입력 창의 글자 잘림을 수정한다.

## 진행한 내용

* 기존 수동 테스트에서 Whale 전역 단축키가 동작하는 것을 확인했다.
* SuddenAttack 앱별 음소거 자체와 `Ctrl + Alt + F8`은 게임에 포커스가 있을 때도 동작했다.
* 단독 `F8`은 Alt+Tab으로 일반 Windows 창에 나온 뒤에는 동작했지만, SuddenAttack이 foreground일 때는 기존 `RegisterHotKey`/`WM_HOTKEY` 경로로 들어오지 않았다.
* modifier가 포함된 단축키는 기존 `RegisterHotKey` 방식을 유지하고, 단독 F1~F11만 Raw Input으로 받도록 `HotkeyService`를 확장했다.
* keyboard top-level collection인 Usage Page `0x01`, Usage `0x06`을 기존 MutePilot window handle에 `RIDEV_INPUTSINK`로 한 번 등록했다.
* `WM_INPUT`에서 `RAWKEYBOARD`를 읽고 현재 설정된 단독 F키와 일치하는 경우에만 기존 mute action을 호출하도록 했다.
* key-down에서 한 번만 실행하고 key-up에서 눌림 상태를 해제해 keyboard auto-repeat가 연속 토글로 이어지지 않게 했다.
* 단독 F키와 modifier 조합을 동시에 등록하지 않도록 경로를 나눴고, MutePilot 내부 중복 검사도 그대로 유지했다.
* 단축키 입력 창을 조금 키우고 표시 상자의 `MinHeight`, padding, 가로·세로 중앙 정렬을 조정했다. 게임에도 F키 입력이 함께 전달될 수 있다는 안내와 modifier 조합 안내도 추가했다.

## 새롭게 알게 된 내용

* `RegisterHotKey`와 `WM_HOTKEY`는 Windows가 등록을 받아 전달하는 전역 단축키 경로이고, Raw Input은 등록한 장치의 입력 정보를 직접 `WM_INPUT`으로 받는 별도 경로다.
* `RIDEV_INPUTSINK`와 대상 window handle을 사용하면 MutePilot이 foreground가 아닐 때도 등록한 keyboard raw input을 받을 수 있다.
* Raw Input을 받는다고 해서 모든 키를 기록할 필요는 없다. 이번 구현은 설정된 단독 F1~F11과 modifier의 현재 눌림 상태만 확인하며 일반 키 입력, 문자열, 입력 이력은 저장하거나 전송하지 않는다.
* `RIDEV_NOLEGACY`를 사용하지 않았기 때문에 F키 입력은 foreground 프로그램에도 계속 전달된다.

## 문제와 해결

SuddenAttack 자체의 오디오 session 제어는 정상이었지만 단독 `F8`만 게임 foreground에서 전달되지 않았다. `Ctrl + Alt + F8`은 같은 상황에서 동작했으므로 오디오 로직을 바꾸지 않고 단독 F키의 입력 경로만 Raw Input으로 보완했다. keyboard hook, 입력 주입, game process 접근, anti-cheat 연동은 사용하지 않았다.

기존 단축키 입력 창은 어두운 표시 상자 안의 조합 문자열이 세로로 잘려 보였다. 창과 표시 영역에 충분한 높이와 padding을 주고 text alignment를 중앙으로 맞췄다.

## 확인 결과

* `dotnet restore MutePilot.sln`: 성공
* `dotnet build MutePilot.sln`: 성공, 경고 0개, 오류 0개
* 경로 분리: 단독 `F8`은 Raw Input, `Ctrl + F8`은 기존 `RegisterHotKey` 경로를 사용하는 것을 확인했다. F12 거부도 유지됐다.
* GUI 실행: 성공. `Master Audio`, `Applications`, 단축키 입력 창이 정상적으로 열렸다.
* Raw Input 초기화: 성공. 시작 시 `RegisterRawInputDevices` 실패 안내가 없었고 기존에 저장된 단독 `F8` 바인딩도 형식 변경 없이 복원됐다.
* 입력 창: 현재 Windows DPI 100%에서 `현재: F8` 문구가 잘리지 않고 표시 영역 중앙에 보이는 것을 창 렌더링으로 확인했다. 125%, 150%는 실제 display scaling 변경 테스트가 남아 있다.
* 자동 검증 중에는 단축키를 누르거나 master/application mute 상태를 변경하지 않았다.
* 개선 후 SuddenAttack foreground에서 단독 `F8`이 실제로 동작하는지는 아직 수동 검증하지 않았다.
